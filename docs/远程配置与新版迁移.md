# 远程配置与新版迁移记录

本文记录 `v3.8.10` 定制迁移后的远程配置入口、版本差异开关和主进程锚点。后续升级先按本文定位新版模块；旧版 `app/electron/main.js` 行号只适用于主进程尚未模块化的版本。

## remote.json 示例与优先级

- 用户配置路径：`%USERPROFILE%\.config\siyuan\remote.json`。
- 完整脱敏示例：`docs/remote.json.example`。复制到上述路径后替换地址和凭据即可；文件按 JSONC 解析，支持行注释、块注释与尾逗号。
- 本仓库仅提供脱敏示例，不包含测试机实际配置或任何真实凭据。
- 参数优先级：命令行 > `remote.json` > 内置默认。`--remote-ssh-failed` 是本地回落会话的内部标记，存在时忽略远程配置；托盘「重试远程模式」会移除该标记并重启。
- 配置预解析：`app/electron/remote/customRemote.js` 的 `resolveCustomRemoteArgument()` 先取得 `remote`，`startup/bootstrap.ts` 再创建目标并初始化隧道。不要删除这一步，否则仅写配置文件而不带 `--remote` 时会错误进入本地模式。

最小配置：

```json
{
  "remote": "https://siyuan.example.com",
  "authCode": "替换为访问授权码",
  "ignoreVersionMismatch": false
}
```

## 忽略版本差异

`ignoreVersionMismatch` 是布尔值，缺省 `false`。设为 `true` 后，允许本地客户端与远程内核的版本号不同，并记录 `ignoring remote kernel version mismatch` 日志。

该开关只放行 `mismatch`：连接失败、超时、无响应、无效版本响应和鉴权失败仍按原逻辑处理。版本差异可能导致 API 或数据格式不兼容，生产环境仍建议保持两端版本一致；不要把它用于掩盖网络故障。

升级时必须保留以下三个检查点，缺一个都可能在启动初期能连接、随后加载本地前端时被再次拒绝：

1. `app/electron/remote/customRemote.js`：从 `remoteConfig.ignoreVersionMismatch === true` 暴露开关；`app/electron/remote/remoteKernel.ts` 的 `shouldIgnoreRemoteVersionMismatch()` 统一判定只允许显式忽略的 `mismatch`。
2. `app/electron/remote/remoteBoot.ts`：首次取得远程版本后，`mismatch` 且开关开启时记日志并继续，否则显示版本不匹配窗口。
3. `app/electron/remote/remoteProtocol.ts`：本地前端文档加载前会再次验证版本，同样允许显式忽略的 `mismatch`。
4. `app/electron/remote/connectionManager.ts`：连接管理窗口的 `check` 命令也读取同一开关。

对应回归测试在 `app/electron/remote/customRemote.test.js`。运行：`pnpm run test:focused electron/remote/customRemote.test.js electron/remote/remoteKernel.test.ts`。

## v3.8.10 主进程模块化映射

上游在 `v3.8.10` 将单个 `main.js` 拆成严格 TypeScript 模块，入口改为 `electron-dist/main.js`。定制代码按下列边界迁移，不能把旧 `main.js` 整文件覆盖回来：

| 功能 | 新版锚点 |
|---|---|
| 配置三级回落、SSH 隧道、重连、HTTP 代理、站点转发、内嵌 SSH Server 状态 | `remote/customRemote.js` |
| 主进程内共享定制实例 | `remote/customRuntime.ts` |
| 配置预解析、启动目标创建、Chromium 开关、默认会话证书策略 | `startup/bootstrap.ts` |
| 等待隧道、自动鉴权、启动超时、失败回落本地 | `remote/remoteBoot.ts` |
| 本地前端协议、站点请求放行、绝对地址改端口、版本二次检查 | `remote/remoteProtocol.ts` |
| webview CSP 与 `frame-ancestors` 处理 | `remote/sessionHeaders.ts` |
| webview 白名单、安全基线和浏览器式快捷键 | `window/windowLifecycle.ts` |
| 远程窗口启用 webview | `window/windowPreferences.ts` |
| 固定窗口标题 | `window/mainWindow.ts`、`ipc/workspace.ts` |
| 托盘 `sr`/`r`/`srf`、重连刷新、重试远程模式 | `ipc/workspace.ts`、`window/trayMenu.ts` |
| `siyuan-get-webview-sites` 与 `siyuan-get-remote-status` | `ipc/register.ts` |
| 定制启动参数不转发给 Chromium | `shared/builtinArgs.ts` |
| SSH 服务与门禁算法 | `electron/sshServer.js`、`electron/webviewGate.js`、`electron/sshOpenSSH.js` |

`customRemote.js` 保留旧版已经验证的网络实现，但接入新版时必须遵守两个顺序约束：

1. `app.commandLine.appendSwitch("host-resolver-rules", ...)` 在创建窗口之前执行。
2. 隧道监听成功后会把目标 origin 改成本机转发端口；必须先 `await tunnelPromise`，再调用 `connectionManager.prepareSession(target)`，否则 Cookie 会写进旧 origin 对应的分区。

## 升级后的检查顺序

1. 使用项目要求的 Node `24.x`，执行 `pnpm install && pnpm run install:electron`，Electron 下载走 `npmmirror`。
2. `pnpm run typecheck`、`pnpm run lint`。
3. `pnpm run test:focused electron/remote/customRemote.test.js electron/remote/remoteKernel.test.ts electron/sshOpenSSH.test.js electron/webviewGate.test.js`。
4. `pnpm run test`，上游测试选择器若判定影响面为全量，不得自行缩小范围。
5. Go 改动执行 `gofmt`，再按公开仓库 `README.md` 的本地构建命令编译内核和 Electron 安装包。
6. 启动绿色版检查日志：配置加载、隧道连接与转发、远程版本、自动鉴权、固定标题和本地前端协议。开启版本忽略时还应出现对应日志。
